# 开发路线图（ROADMAP）

版本：v1.0 规划稿 ｜ 日期：2026-11-19 ｜ 前置阅读：PRODUCT / ARCHITECTURE / SIMULATION

原则：**先让引擎正确，再让画面好看，最后让游戏好玩。** 每个阶段结束必须通过验收清单才能进入下一阶段；每阶段结束时产品都处于可运行、可演示状态。

## P0 — 地基：脚手架 + 纯引擎（预计 1–2 个开发日）

任务：
1. Vite + React + TS(strict) + Tailwind v4 + Vitest 脚手架；目录按 ARCHITECTURE 第 6 节落地。
2. `simulation/types.ts` 全部契约、`config.ts` 默认假设。
3. `rng.ts`：xmur3 + mulberry32 + 子流 + Box–Muller。
4. `engine.ts`：stepYear（含两阶段事件步进接口，事件匹配先留空实现）、replay。
5. `goals.ts`、`endings.ts`（判定逻辑，文案模板可占位）。
6. SIMULATION 第 7 节测试清单 1–6、8 全部落地。

验收标准：
- [x] `npm run dev` / `build` / `test` 三条命令可用（命令写入 AGENTS.md）。
- [x] Vitest 全绿：确定性、守恒、通胀口径、修正生命周期、判定边界、截断重播。
- [x] `simulation/`、`events/` 无任何 React/DOM/Math.random 引用（用 lint 规则或 grep 检查脚本验证）。
- [x] 用一段临时脚本跑 30 岁 / 20 万资产 / 20 万收入 / 12 万支出的默认局，输出逐年表格，人工抽查 3 个年份的手算一致。

## P1 — 看得见的人生：输入页 + 播放 UI（预计 2–3 个开发日）

任务：
1. design tokens：深色背景、绿/青主色、大字号数字字体层级、玻璃卡片样式。
2. 开局页：4 输入 + 目标模式开关 + 校验 + 随机人生按钮（视觉按 PRODUCT 4.1，第一眼标准）。
3. playback 状态机 + rAF driver（1.1s/年，1×/2×/4×，暂停/继续）。
4. 模拟页：HUD、Motion 数字滚动、ECharts 逐年生长曲线 + 动态目标虚线、实际购买力小字。
5. 本阶段无事件：引擎事件匹配保持空，一局直通结局（结局页先用最简占位）。

验收标准（2026-11-19 完成，dev 与生产构建均实测）：
- [x] 打开页面到第一年数字变化 ≤ 3 秒；默认值下 30 秒内可开局。
- [x] 数字滚动与曲线逐年平滑生长，无跳变、无整页重渲染卡顿（增量 setOption；Performance 面板抽查未做，留 P4）。
- [x] 暂停/继续/变速正确；暂停时数字与曲线完全静止。
- [x] 曲线目标线与 HUD「距目标差额」口径一致（名义），小字实际购买力换算正确。
- [x] 移动端宽度 375px 下布局不破（基础可用即可，精修在 P4）。
- [x] 视觉评审：开局页与模拟页截图对照 PRODUCT 第 6 节「避免清单」，无后台管理感（截图存 .qa/）。

## P2 — 游戏的核心：事件与抉择（预计 2–3 个开发日）

任务：
1. `events/matcher.ts`：节奏控制（首事件 2–4 年、概率递增、最小间隔）+ 门槛过滤 + 加权抽取。
2. 16 个事件定义数据（SIMULATION 5.2 全量）+ hint 与 effects 一致性静态校验测试。
3. EventCard 弹窗（Motion 进出场、背景压暗）、选项按钮、选择后结果飘字。
4. 两阶段步进接通：事件暂停 → 选择 → 当年现金更新曲线点 → 次年斜率变化。
5. 事件时间线抽屉（回顾已发生事件与选择）。
6. debt-crisis 强制救援流程。

验收标准（2026-11-20 完成，无头 Chrome 真实渲染实测）：
- [x] 首事件落在第 2–4 年；全局最小间隔 2 年（测试 + 多种子统计）。长局（≥28 年）平均 9.6 事件；短 FIRE 局更少（节奏符合预期，未为凑数破坏门槛）。
- [x] 每个选项的 hint 数字与实际引擎效果一致（events-data.test.ts 全量静态校验 17 事件所有选项）。
- [x] 一次性现金影响出现在当年曲线点；持续性影响次年生效；历史点不被改写（测试 + 浏览器选择前后资产核对）。
- [x] 改选某事件后重播，其余年份市场收益序列不变（子流隔离测试）；同种子同选择两次真实浏览器运行逐年完全一致。
- [x] 新增一个测试事件只需加数据文件，不改引擎代码（延迟剧情经 scheduleEvent/scheduledCash 数据驱动，引擎不识别任何具体事件 id）。
- [x] 事件弹窗质感评审：深色玻璃 + 分类渐变、Motion 弹入、背景压暗模糊，375px 可读可点（截图 .qa/event-*.png）。

## P3 — 结局与循环：结局页 + 重播 + 分享（预计 2 个开发日）

任务：
1. 结局判定全分支接通（fire 分档 / end 分档 / bankrupt / 开局即 FIRE 彩蛋）。
2. 结局页：称号、叙事文案（模板 + 关键事件拼接）、4 个关键数字、带事件标记的完整曲线。
3. 「换一种人生」「随机新人生」「回到关键抉择」（事件列表改选 → 截断 choices 同种子重播）。
4. `share.ts`：ReplayData ⇄ URL hash；分享链接打开 → 「观看 TA 的人生」自动重播 /「同样开局玩自己」。
5. localStorage 持久化：刷新后从最后选择处恢复。

验收标准（2026-11-20 完成，无头 Chrome 真实渲染实测 30 项检查全过）：
- [x] 四类结局均可通过构造输入稳定触发并展示正确称号与叙事（FIRE「大器晚成」/ 破产「财务重启」/ 开局即 FIRE「你本来就自由了」隐藏结局 / end 分档由既有测试覆盖）。
- [x] 分享链接在另一浏览器上下文（独立 localStorage，等价隐身窗口）重播，逐年资产完全一致（40 年 JSON 深相等）。
- [x] 「回到关键抉择」改选后，分歧点之前曲线完全一致，之后合理变化（t=5 改选 expand→close：前 5 年逐年一致，t8 延迟结算随分支取消）。
- [x] 模拟中途刷新页面，恢复后继续播放，历史与选择无丢失（playing/paused/eventPending/选择后/结局/开局 FIRE 六种存档状态均实测）。
- [x] 版本不匹配的 hash 数据被拒绝并给出中性提示，不白屏（损坏 base64 与 v:2 均实测）。
- [x] 完整游戏循环手动走查：开局 → 事件 → 结局 → 改选重播 → 分享，无断点（真实 UI 点击完成）。
